# План развития сайта buhpartner.ru

Документ описывает, что уже сделано, какие проблемы найдены при аудите и что делать дальше — по приоритетам.
Дата аудита: 18.11.2026.

---

## 1. Текущее состояние

Сайт — статический лендинг на чистом HTML/CSS/JS, хостинг GitHub Pages, домен `buhpartner.ru`.

* 5 страниц: `index.html`, `contacts.html`, `checklist.html`, `privacy-policy.html`, `404.html`
* Интерактив: калькулятор стоимости, 3 формы (заявка, лид-магнит, контакты), аккордеон FAQ, модалка чек-листа, баннер согласия на ПД, кнопка Max
* SEO-основа: meta description, canonical, Schema.org разметка (Organization, LocalBusiness, FAQPage, BreadcrumbList, Service), sitemap.xml, robots.txt
* Аналитика: Яндекс.Метрика (20397475) — **только на index.html**; GA4 — заглушка

## 3. План действий

### 🔴 Приоритет 1 — починить и заработать (бизнес-ценность)

**P1.1 — Исправить SEO-баги B1, B2, B6, B7, B8, B10, B11**
* Заменить `bukhpartner.ru` → `buhpartner.ru` в canonical и og:image (`index.html`)
* Убрать 404.html из sitemap.xml, поставить ему `<meta name="robots" content="noindex">`, убрать canonical
* В Schema.org заменить `favicon.svg` на реальный путь или data URI
* Убрать «beforehand» из description чек-листа
* Почистить robots.txt и мусорный комментарий
* *Результат: главная корректно индексируется, шеринг работает, ошибок в валидаторах нет*

**P1.2 — Подключить отправку форм (B3) — ✅ КОД ГОТОВ, ждёт хостинг и токен**

Канал доставки: **мессенджер MAX** (решено владельцем). Архитектура:

```
Сайт (GitHub Pages) → js/forms.js → POST /api/lead → сервер-прокси (Node.js)
                                                        └→ platform-api2.max.ru → личный диалог с ботом
```

Что сделано:
* `js/forms.js` — общий обработчик всех 3 форм: `fetch()`, 1 retry, таймаут 15 с,
  honeypot от спама, антиспам-лимит по IP, UTM/реферер/страница в заявке,
  цели Метрики/GA (`lead_submit`, `lead_submit_error`), фолбэк-телефон при ошибке
* Формы подключены: `index.html` (заявка + лид-магнит), `contacts.html` —
  добавлены `name`-атрибуты и `data-lead-form`, старые `console.log`-обработчики удалены
* `server/index.js` — сервер-прокси на чистом Node.js 18+ (без зависимостей):
  CORS только для доменов сайта, лимит заявок, валидация, форматирование сообщения,
  отправка в MAX с корневым сертификатом Минцифры (`server/certs/`)
* `server/get-chat-id.js` — одноразовый скрипт получения `chat_id` (long polling)
* `server/README.md` — инструкция: создание бота на платформе MAX для партнёров,
  получение токена, настройка, развёртывание
* `.gitignore` — `server/.env` (токен) в репозиторий не попадает
* Проверено локально: health, CORS, валидация, полный путь до API MAX
  (с фиктивным токеном — ответ `401 Invalid access_token`, TLS и запрос работают)

Осталось (нужны решения/действия владельца):
1. Создать бота на платформе MAX для партнёров → токен (см. `server/README.md`, шаг 1)
2. Нажать боту «Начать» → `node server/get-chat-id.js` → записать `MAX_CHAT_ID` в `server/.env`
3. Выбрать и задеплоить хостинг (VPS / Yandex Cloud Functions — варианты в `server/README.md`)
4. Вписать URL сервера в `js/forms.js` → `LEAD_ENDPOINT` и опубликовать сайт
   (пока не вписан — тестовый режим: заявки видны только в консоли F12)
* *Результат: каждая заявка доходит до владельца в MAX*

**P1.3 — Аналитика (B4, B5, B9)**
* Решить по GA4: вставить реальный ID **или удалить** заглушку (пока оставить — нельзя)
* Добавить Метрику на все 5 страниц (один и тот же сниппет)
* Настроить цели в Метрике: `form_submit` (3 формы), `click_cta` (кнопки), `calculator_use`, `checklist_download`, `click_max`
* Реализовать через `ym(20397475, 'reachGoal', '...')` и `gtag('event', ...)`
* *Результат: видно, откуда приходят заявки и что мешает конверсии*

**P1.4 — Превью для соцсетей (B12)**
* Создать `preview.jpg` 1200×630 (логотип «Б», телефон, слоган) и положить в корень
* Создать `favicon.svg` (или оставить инлайновый, но убрать битые ссылки)
* *Результат: красивое превью при шеринге в Telegram/VK/WhatsApp*

### 🟡 Приоритет 2 — рост трафика и конверсии

**P2.1 — Блок отзывов клиентов**
* 5–7 отзывов с именем, городом, типом бизнеса (ИП/ООО)
* Разметка `Review`/`AggregateRating` в Schema.org — звёздочки в выдаче Google
* *Зачем: социальное доказательство повышает конверсию на 15–30%*

**P2.2 — Отдельные страницы услуг (SEO)**
* `/uslugi/ip.html` — бухгалтерское сопровождение ИП
* `/uslugi/ooo.html` — сопровождение ООО
* `/uslugi/nalogovyj-audit.html` — налоговый аудит
* `/uslugi/antikrizis.html` — антикризисное управление
* На каждую: H1 с ключевым словом, свой description, кейс, CTA-форма, breadcrumbs
* Обновить sitemap.xml, добавить ссылки из меню/футера
* *Зачем: отдельные страницы лучше ранжируются по коммерческим запросам, чем один лендинг*

**P2.3 — Блог «Налоговый вестник»**
* 2–4 статьи в месяц: разборы изменений в законодательстве, «что проверяют в 2026 году», «самые частые ошибки на УСН»
* Каждая статья — лид-магнит (чек-лист, консультация) в конце
* *Зачем: долгосрочный поток бесплатного трафика из поиска*

**P2.4 — Форма «Обратный звонок» + виджет чата**
* Кнопка «Заказать звонок» в хедере — модалка с полем телефона
* Мини-виджет чата (ТЛГ-виджет или кнопка Max с раскрытием)

**P2.5 — Cookie-баннер**
* Отдельный баннер для аналитики/маркетинговых cookie (сейчас только баннер ПД по 152-ФЗ)
* Согласие сохранять в localStorage, не грузить Метрику до согласия, если потребуется
