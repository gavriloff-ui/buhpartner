# Сервер-прокси: заявки сайта → мессенджер MAX

Небольшой HTTP-сервер на чистом Node.js (18+) **без единой зависимости**.
Принимает формы с сайта и отправляет заявки в ваш диалог с ботом MAX.

Почему нужен прокси, а не отправка прямо из браузера:

1. **Токен бота не должен быть в HTML/JS сайта** — иначе любой сможет
   рассылать сообщения от вашего имени.
2. **CORS**: у API MAX нет заголовков CORS — браузер не сможет вызвать его напрямую.
3. **TLS**: API MAX использует сертификаты НУЦ Минцифры
   (`Russian Trusted Root CA`), которым не доверяют браузеры и стандартные
   CA-бандлы. Корень лежит в `server/certs/` и передаётся в `ca:` при запросе.

## Структура

```
server/
├── index.js          # сам сервер (POST /api/lead → MAX)
├── get-chat-id.js    # одноразовый скрипт: узнавание chat_id
├── .env.example      # шаблон настроек
├── certs/            # корневой сертификат Минцифры (для TLS к API MAX)
└── README.md         # этот файл
```

## Шаг 1. Создать бота в MAX (однократно)

1. Зайдите на **платформу MAX для партнёров** → https://dev.max.ru
   (подключение доступно юрлицам, ИП и самозанятым — резидентам РФ;
   нужен верифицированный профиль организации).
2. Создайте чат-бота, задайте имя (например `buhpartner_bot`) и описание.
3. В настройках бота скопируйте **токен доступа** (access token).
   Он понадобится в `MAX_BOT_TOKEN`. Подробнее: https://dev.max.ru/docs/chatbots/bots-create/create

## Шаг 2. Получить chat_id (однократно)

Заявки отправляются в **личный диалог с ботом**, поэтому нужен chat_id этого диалога:

```bash
# токен — из шага 1 (или положите его сразу в server/.env)
MAX_BOT_TOKEN=XXXX node server/get-chat-id.js
```

Скрипт начнёт «слушать» события (long polling). В этот момент **напишите боту
в MAX и нажмите «Начать»** (или откройте ссылку `https://max.ru/<имя_бота>?start=site`).
В ответ придёт событие `bot_started` — скрипт выведет `chat_id`, его и нужно записать в `.env`.

## Шаг 3. Настройка

```bash
cd server
cp .env.example .env
# отредактируйте .env: впишите MAX_BOT_TOKEN и MAX_CHAT_ID
```

Файл `.env` добавлен в `.gitignore` — в репозиторий он не попадёт.

## Шаг 4. Локальная проверка

```bash
node server/index.js
# в другом терминале:
curl -s -X POST http://localhost:8080/api/lead \
  -H 'Content-Type: application/json' \
  -d '{"name":"Тест","phone":"+7 900 000-00-00","source":"Тест","page":"/"}'
# и проверьте: сообщение пришло в MAX
```

`GET /health` возвращает состояние настроек: `{"ok":true,"token":true,"chat":true}`.

## Шаг 5. Развёртывание (хостинг пока не выбран — варианты)

Код переносимый, работает везде, где есть Node.js 18+:

### Вариант А. Любой VPS (Timeweb, Selectel, регион РФ)

```bash
# на сервере (желательно с русским IP — к API MAX из-за рубежа могут быть проблемы)
git clone <репозиторий> && cd buhpartner/server
cp .env.example .env   # заполнить
# systemd-юнит / запуск через pm2:
pm2 start index.js --name buhpartner-leads && pm2 save
# nginx как reverse-proxy на localhost:8080 + TLS (certbot)
```

Рекомендуется поставить сертификаты Минцифры системно (для любых внешних
проверок, не только для этого скрипта):

```bash
sudo cp certs/*.crt /usr/local/share/ca-certificates/
sudo update-ca-certificates
```

### Вариант Б. Yandex Cloud Functions

Без изменений кода: функция Node.js 20, handler `server/index.js`,
переменные окружения `MAX_BOT_TOKEN`, `MAX_CHAT_ID` — в настройках функции
(токен не попадёт в код). Папка `certs` уезжает вместе с кодом, путь
`path.join(__dirname, 'certs', ...)` работает как есть. В триггере задайте
URL, впишите его в `js/forms.js` → `LEAD_ENDPOINT`.

### Подключение сайта (после развёртывания)

1. Впишите URL сервера в `js/forms.js` → `LEAD_ENDPOINT` (иначе формы
   работают в тестовом режиме и заявки никуда не уходят).
2. Закоммитьте и опубликуйте сайт (GitHub Pages).

## Эндпоинты

| Метод | Путь       | Назначение                                  |
|-------|------------|---------------------------------------------|
| GET   | `/health`  | проверка настроек                           |
| POST  | `/api/lead`| приём заявки с сайта → отправка в MAX       |

Полезная нагрузка `POST /api/lead` (JSON): `name` (обязательно),
`phone` и/или `email` (хотя бы одно), `message`, `source`, `page`,
`referrer`, `utm` (объект), `ts`, `_gotcha` (honeypot).

Защита: CORS только для доменов `ALLOWED_ORIGINS`, лимит по IP
(`RATE_LIMIT` заявок за `RATE_WINDOW_MS`), honeypot-поле против ботов,
необязательный общий секрет `X-Lead-Secret`, токен MAX — только на сервере.

## Ограничения API MAX

- текст сообщения ≤ 4000 символов;
- ≤ 2 сообщения в секунду в один диалог, ≤ 30 rps всего;
- заголовок `Authorization: <токен>` (без префикса `Bearer`);
- продакшен-рекомендация MAX — Webhook (`POST /subscriptions`),
  long polling (`GET /updates`) допустим, но пригоднее для разовых задач
  (как get-chat-id.js).
